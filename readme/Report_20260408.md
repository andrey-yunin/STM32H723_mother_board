# Отчет о текущем состоянии и аудите Дирижера (Экосистема DDS-240)

## Дата: Среда, 8 апреля 2026 г.

В ходе анализа была проведена проверка соответствия текущей прошивки Дирижера (Conductior) новым стандартам экосистемы DDS-240, зафиксированным в `readme/DDS-240_eko_system/`.

---

## 1. Результаты аудита: Дирижер vs. Стандарт (Плата насосов и клапанов)

| Характеристика | Стандарт экосистемы | Текущее состояние | Вывод |
| :--- | :--- | :--- | :--- |
| **Bitrate** | 500 kbps | Сконфигурирован (Classic CAN) | Соответствует |
| **ID Format** | 29-bit Extended | Используется в `can_packer` | Соответствует |
| **NodeID** | Conductor (0x10), Pump (0x30) | Прописаны в `can_packer.h` | Соответствует |
| **Payload DLC** | Строго 8 байт (DLC=8) | Используется 3-4 байта | **НЕ СООТВЕТСТВУЕТ** |
| **Payload Format** | `[CMD_LE][DEV_ID][TIMEOUT_LE][RES]` | `[CMD_LE][DEV_ID]` | **НЕ СООТВЕТСТВУЕТ** |
| **Команды клапанов**| 0x0204 (Open), 0x0205 (Close) | Не реализованы | **ОТСУТСТВУЮТ** |
| **Сервисные команды**| 0xF001 - 0xF00F | Не реализованы | **ОТСУТСТВУЮТ** |
| **Маппинг ID** | Насосы (10-22), Клапаны (23-25) | Насосы промывки (10-11) | Требует расширения |

---

## 2. Ключевые выводы

1.  **Инфраструктурная готовность**: Дирижер уже обладает необходимыми абстракциями (`can_packer`, `job_manager`), что позволяет произвести интеграцию путем точечных правок, а не переписывания системы.
2.  **Критическое несоответствие**: Текущий формат упаковки CAN-кадров (DLC < 8) приведет к неработоспособности при взаимодействии с реальной прошивкой исполнителя на базе STM32F103, ожидающей полные 8 байт.
3.  **Необходимость фильтрации**: Контроллер FDCAN Дирижера на данный момент не настроен на прием расширенных ID от узлов-исполнителей, что делает невозможным получение ACK/DONE подтверждений.

---

## 3. Утвержденная стратегия

Принято решение начать интеграцию с **Этапа 1: Модернизация `can_packer`**, что создаст совместимый транспортный уровень, а затем переходить к синхронизации высокоуровневых команд пользователя.
