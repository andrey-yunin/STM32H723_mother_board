### **3.1. Главная задача: Передача параметров в рецепты**                                                                                                                                                         
                                                                                                                                                                                                                   
**Концепция решения: "Выделенный Парсер Параметров с Транслятором Параметров"**                                                                                                                                    
                                                                                                                                                                                                                   
**Главная цель: Обработка динамических параметров команд пользователя для атомарных команд, включая сложные преобразования.**                                                                                      
                                                                                                                                                                                                                   
Идея заключается в том, чтобы централизовать всю логику разбора параметров в одном месте (`parameter_parser`), но вынести сложные расчеты, связанные с геометрией и механикой устройства, в отдельный модуль (`param_translator`). Это обеспечивает чистоту архитектуры, масштабируемость и легкость тестирования.                                                                                                                    
                                                                                                                                                                                                                   
1.  **Новый модуль `param_translator`**: Создается новый модуль (`param_translator.c` и `.h`), который будет отвечать за преобразование высокоуровневых параметров (например, номер кюветы) в низкоуровневые аппаратные действия (например, количество шагов мотора).                                                                                                                                                                   
2.  **Модуль `parameter_parser`**: Теперь он отвечает за:                                                                                                                                                          
    *   Чтение сырых байтов из входящей команды.                                                                                                                                                                   
    *   Вызов функций из `param_translator` для выполнения необходимых расчетов (например, `ParamTranslator_CuvetteToSteps(cuvette_number)`).                                                                      
    *   Сохранение *рассчитанных, готовых к использованию* значений (например, `rotate_steps`) в структуру `ParsedArgs_WashStationWash`.                                                                           
3.  **Функция `Parameters_Parse`**: Внутри `parameter_parser` эта функция берет сырые байты параметров из `UniversalCommand_t` и преобразовывает их в структурированные формы (например, `ParsedArgs_Init`, `ParsedArgs_DispenserWash`, `ParsedArgs_WashStationWash`), заполняя соответствующие поля в `cmd->args` и устанавливая `cmd->args_type = ARGS_TYPE_PARSED`. Важно, что здесь же происходит вызов функций `param_translator` для расчета производных параметров.                                                                                                                                                                               
4.  **Единая точка входа**: `Parser_ProcessBinaryCommand` после нахождения команды в таблице и отправки `ACK` вызывает `Parameters_Parse`, передавая ей `UniversalCommand_t` для заполнения разобранными и рассчитанными параметрами.                                                                                                                                                                                                 
5.  **Связь с `AtomicAction_t` через `ParamSource_t`**: После того как `UniversalCommand_t` будет заполнена разобранными и рассчитанными параметрами, `JobManager` будет использовать эти данные. `AtomicAction_t` теперь включает поле `ParamSource_t` для каждого своего параметра, которое указывает, откуда брать значение: либо из статического определения рецепта, либо из динамически полученных и рассчитанных параметров (`UniversalCommand_t`) пользовательской команды (например, `PARAM_SOURCE_CMD_INIT_MASK`, `PARAM_SOURCE_CMD_DISPENSER_VOLUME`, `PARAM_SOURCE_CMD_WASH_STATION_WASH_ROTATE_STEPS`). Это обеспечивает гибкость и позволяет рецептам использовать параметры, предоставленные пользователем, в уже подготовленном виде.                                                                                                                       
                                                                                                                                                                                                                   
**Преимущества:**                                                                                                                                                                                                  
*   **Четкое разделение ответственности**: `command_parser` идентифицирует команду, `parameter_parser` разбирает ее параметры и выполняет преобразования с помощью специализированных модулей (`param_translator`), а `JobManager` исполняет рецепт, используя уже готовые, структурированные параметры.                                                                                                                              
*   **Высокая масштабируемость**: Добавление новой параметризованной команды требует лишь добавления соответствующего `case` в `switch` в `parameter_parser.c` и обновления `UniversalCommand_t`, без изменения ядра `JobManager` или `command_parser.c`. Сложные расчеты выносятся в отдельные, тестируемые модули.                                                                                                                  
*   **Улучшенная читаемость и обслуживаемость**: Вся логика парсинга и расчета находится в выделенных файлах, что упрощает их поиск, понимание и модификацию.                                                      
*   **Гибкость рецептов**: `ParamSource_t` позволяет рецептам быть более универсальными, адаптируясь к динамическим входным данным от пользователя в уже подготовленном виде.

**Детальный анализ команд для интеграции с `param_translator`:**                                                                                                                                                   
                                                                                                                                                                                                                   
**Вывод:** Многие команды имеют параметры, которые являются высокоуровневыми или физическими величинами и могут быть преобразованы в низкоуровневые аппаратные значения с помощью `param_translator`.             
                                                                                                                                                                                                                   
Основными категориями для трансляции являются:                                                                                                                                                                     
*   **Номер кюветы/слота** -> Шаги мотора для позиционирования (X, Y, вращение).                                                                                                                                   
*   **Объем жидкости** -> Длительность работы насоса.                                                                                                                                                               
*   **Температура** -> Сырые значения для термоконтроллера/ЦАП.                                                                                                                                                   
*   **Смещение по Z** -> Шаги мотора по оси Z.
