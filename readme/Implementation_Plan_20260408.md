# План интеграции Дирижера с экосистемой DDS-240 (Advanced Level)

## Дата: Среда, 8 апреля 2026 г.

Этот документ фиксирует стратегию и конкретные шаги по приведению ПО Дирижера в соответствие с новыми стандартами экосистемы и обеспечению взаимодействия с исполнителем насосов и клапанов.

---

## 1. Цели интеграции
1.  **Полная совместимость по протоколу CAN**: Переход на 29-битные ID и строгое соответствие DLC=8 для всех команд управления жидкостью.
2.  **Синхронизация реестра устройств**: Приведение `device_mapping.h` к единому стандарту (Насосы 10-22, Клапаны 23-25).
3.  **Реализация сервисного слоя**: Поддержка команд `0xFxxx` (Get Info, Reboot и т.д.) для управления жизненным циклом исполнителей.
4.  **Восстановление "слуха"**: Настройка фильтров FDCAN для приема ответов от реальных устройств.

---

## 2. Этапы реализации

### **Этап 1: Обновление транспортного уровня и упаковщика (can_packer)**
*   [ ] **1.1. Синхронизация `can_protocol.h`**: Заменить локальный файл `App/Inc/Dispatcher/command_protocol.h` или дополнить его константами из `readme/DDS-240_eko_system/can_protocol.h`.
*   [ ] **1.2. Модернизация `can_packer.h`**: Добавить прототипы для новых команд (Клапаны, Сервис).
*   [ ] **1.3. Рефакторинг `can_packer.c`**:
    *   Установить `DLC=8` для всех команд `0x02xx`.
    *   Добавить поле `timeout` (байты 3-6) в упаковщики насосов.
    *   Реализовать функции: `Packer_CreateRunDurationPumpMsg`, `Packer_CreateOpenValveMsg`, `Packer_CreateCloseValveMsg`.
    *   Реализовать сервисную команду `Packer_CreateGetDeviceInfoMsg (0xF001)`.

### **Этап 2: Синхронизация логических уровней**
*   [ ] **2.1. Обновление `device_mapping.h`**: Переопределить ID для насосов (10-22) и клапанов (23-25).
*   [ ] **2.2. Трансляция команд**: Проверить и обновить `param_translator.c`, чтобы высокоуровневые команды пользователя корректно вызывали обновленные упаковщики CAN.

### **Этап 3: Настройка аппаратного уровня (FDCAN)**
*   [ ] **3.1. Конфигурация фильтров**: В `main.c` настроить фильтры на прием расширенных ID от узлов `0x20` (Моторы), `0x30` (Насосы), `0x40` (Термо).
*   [ ] **3.2. Активация прерываний**: Раскомментировать код запуска CAN и уведомлений в `task_can_handler.c`.

### **Этап 4: Тестирование и Валидация**
*   [ ] **4.1. Обновление симулятора**: Добавить в `executor_simulator.c` поддержку новых команд и проверку DLC=8.
*   [ ] **4.2. Системный тест**: Запуск существующих Python-тестов для проверки, что цепочка "Команда пользователя -> Дирижер -> CAN (имитатор) -> Ответ" не сломалась.

---

## 3. Ожидаемые риски
*   **Конфликт ID**: Возможные накладки при изменении `device_mapping.h` в существующих рецептах.
*   **Таймауты**: Необходимость точной настройки времени ожидания ACK (50мс) в `job_manager`.
